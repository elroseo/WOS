# PARA Guide

PARA organizes information according to what you can do with it now.

## Projects

Projects are active outcomes with a finish line. Examples include completing a certification, preparing a customer deliverable, or resolving a defined investigation.

Move a project to `40 Archives/Projects` when its outcome is complete or abandoned.

## Areas

Areas are responsibilities that continue over time. Accounts, professional development, relationships, daily work, and work-management practices belong here.

Areas should describe a standard to maintain rather than a task to finish.

## Resources

Resources are topics that may support future work. Product notes, runbooks, cheatsheets, tooling documentation, writing guidance, and reusable support insights belong here.

## Archives

Archives contain inactive material from the other categories. Archiving keeps active folders focused without deleting useful history.

## Inbox

Inbox is a temporary capture location, not a permanent category. During review, move each item to a Project, Area, Resource, or Archive.

## Classification test

Ask these questions in order:

1. Does this support an active outcome? Put it in Projects.
2. Does this support an ongoing responsibility? Put it in Areas.
3. Is it reusable reference material? Put it in Resources.
4. Is it inactive but worth retaining? Put it in Archives.
5. Am I unsure? Keep it in Inbox until the next review.

## Tool responsibilities

- Obsidian is the editor and source of truth.
- PARA determines where information belongs.
- QMD retrieves relevant content.
- Graphify explores relationships.
- Git records changes and backs up the vault to a private remote.
