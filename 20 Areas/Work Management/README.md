# Work Management

This area defines how I capture, prioritize, review, and complete work. The task dashboard is my normal homepage; I do not maintain a separate daily-note system.

## Source of truth

- [[Task Dashboard - Filtered]] is the homepage and consolidated view of open work.
- [[Task Inbox]] is the quick-capture location for tasks without an existing context note.
- Tasks tied to a customer, meeting, person, project, or learning note should stay in that note so the reason and evidence remain nearby.
- The dashboard collects tasks across the vault, regardless of where they are stored.

## Operating rhythm

### Start of work

1. Open [[Task Dashboard - Filtered]].
2. Check overdue, due-today, and high-priority tasks.
3. Select the smallest set of outcomes that must move today.
4. Review meetings or customer commitments that create a fixed deadline.

### During the day

- Capture an unclassified task in [[Task Inbox]].
- Put customer actions in the relevant customer or meeting note.
- Put learning actions beside the reference or practice material.
- Add a due date only when the date represents a real commitment.
- Use priority to distinguish impact, not anxiety.
- Complete or rewrite stale tasks instead of carrying ambiguous reminders indefinitely.

### End of work

1. Mark completed work.
2. Record the next concrete action for anything still active.
3. Move useful investigation methods or lessons into Resources.
4. Ensure customer commitments have an owner and expected follow-up date.

### Weekly review

1. Process uncategorized tasks in [[Task Inbox]].
2. Review overdue and undated high-priority work.
3. Review active projects for a clear next action.
4. Review customer commitments and recurring responsibilities.
5. Review professional-development and certification progress.
6. Remove, rewrite, or defer work that is no longer actionable.

## Task conventions

- Write tasks as a concrete action with an observable result.
- Keep the supporting context in the same note whenever possible.
- Use recurring tasks only for genuine repeating responsibilities.
- Do not create a project for a single task.
- Promote multi-step outcomes with a finish line into `10 Projects/`.
- Keep ongoing standards and recurring responsibilities in `20 Areas/`.
- Move reusable instructions, methods, and references into `30 Resources/`.
